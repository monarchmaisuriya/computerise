# Computerise

Computerise lets Paseo agents see and control the main display of the Mac running the Paseo daemon. It works across agent providers through thirteen MCP tools for screenshots, accessibility snapshots, pointer position, clicking, moving, dragging, scrolling, typing, key presses, zooming, opening apps, short waits, and a status report. A click, move, or scroll can name a control by its number from the last accessibility snapshot; the action is refused if that control changed since, including a row, cell, or text whose content changed (a text field may change as you type into it). Every input action reports what changed in the front window's controls, or that nothing visible to the accessibility tree changed, and can also return a screenshot taken just after it.

New agents start in **Ask before actions**: they can take screenshots and accessibility snapshots without asking, and each input action waits for you to approve it in the agent chat or the Computer panel. Paseo does not mark the agent as needing input, so the Paseo desktop app also shows a desktop notification naming the chat; if notifications are turned off for Paseo, a request you miss times out after the approval timeout. The timeout is **Wait for an answer** in the plugin settings, from 5 seconds to 30 minutes, default 1 minute. An agent's own client gives up on a tool call after about a minute, so the plugin raises that limit to 31 minutes for the Claude chats it equips, which also applies to the chat's other HTTP tool servers; while a card waits, the plugin tells Claude the call is still in progress and keeps that chat's hold on the screen. Codex chats, and chats created before v0.7.0, stop waiting after 55 seconds whatever the setting says. Choose **Automatic** to let that agent act without individual approvals, except key presses with cmd, ctrl, or option, which always ask because they can be another app's global shortcut (for example a password manager's quick-access key). Choose **Off** to take its access away. Turning an agent off, or from automatic to ask, takes effect at once: the macOS step it is running is interrupted, and an action that had not posted its input yet does nothing. In ask mode, **Allow <app> this turn** on a click, move, drag, or scroll also allows later pointer actions in that app until the agent's turn ends, the agent closes, its mode changes, or computer use is stopped. Typing, key presses, opening apps, and drags between two apps always ask. A request still waiting when the turn ends, the agent closes, its mode changes, or the agent's tool call times out is withdrawn and does nothing; an approval card never appears after the turn it belongs to has ended. Read-only screenshots and accessibility snapshots never ask while the agent's mode is ask or auto. One agent holds the screen at a time, and **Stop computer use** immediately cancels pending approvals, releases that lease, and interrupts the macOS step that is running, such as a long piece of typing.

## Setup

This source version requires a Paseo host exposing `adaptiveAgentFeatures`; setup stops with update guidance on older hosts. A released minimum SDK/host version has not been assigned, and the existing package metadata is not an installation guarantee. In **System Settings → Privacy & Security**, grant **Screen & System Audio Recording** and **Accessibility** to Paseo. Reopen Paseo after granting screen recording. The Computer panel shows both permissions and can open the matching System Settings pane, ask macOS to show its Accessibility prompt, and check Screen Recording without waiting for an agent's screenshot. No additional software is installed.

Computer tools are derived on each interactive session open, not saved at creation. HTTP tool delivery, instructions, exact automatic approvals and the Claude timeout environment are checked independently. Without HTTP support, Computerise creates no tool token or timeout override. Without supported exact approvals, tools remain available with ordinary provider permission prompts; Computerise does not answer those prompts automatically. Its own action approvals and safety checks still run. Explicit caller environment values are not overwritten.

New agents start in ask mode. Agents that had the computer tools before v0.5.0, when the default was off, stay off until you choose a mode. A child of an Off agent starts Off even if HTTP tools are unavailable at its first open. A temporary limitation never clears a retained mode or seat. Use `/computer auto`, `/computer off`, or `/computer ask` to change one agent's mode, or the Computer button in the workspace header to change every known chat in that workspace at once. Changing Off to Ask or Automatic permits tools on the next eligible session open; it does not restart the session. The header and panel distinguish retained mode from installed tool delivery, and keep mode controls and Stop usable. If the plugin's saved modes cannot be read, every agent that already has the tools is set to off.

An unadopted saved `paseo-computerise` endpoint suppresses the entire new computer contribution group before allocation. Its endpoint, instructions, grants and environment stay unchanged, including while mode is Off. Computerise observes a saved credential only when its signature and scope verify, the endpoint matches its running server, and its seat is already bound to this exact agent. It never binds or repairs a saved credential. Invalid credentials remain a visible error. Saved instruction markers suppress duplicate guidance even after endpoint-only adoption. Explicit host preview/apply/reset controls adoption; the previous value overwritten by the historic MCP timeout merge cannot be recovered, so adopting that environment field needs an explicit baseline. Original saved configuration is retained by the host; review/reset adoption receipts before downgrading to a host that does not understand them.

Fixed MCP/process bindings with prior owned computer contributions reuse only the same live plugin instance's installed prior contribution through `launch.retainPrevious()`. Computerise checks the current mode, HTTP support, instructions, exact grants, configured port, signed seat binding and its contributed environment keys before reuse. The prior credential, prompt and grants stay exact. Changed unrelated caller environment is preserved. Turning that binding Off, incompatible support or settings, conflicting caller-owned environment, or a missing live prior contribution reject with full-close/reopen guidance before provider access. A fixed opening without prior owned computer contributions stays unavailable without allocating a seat or credential; Off and saved caller endpoints remain unchanged.

### Source-verification limits

`PluginSessionOpenContext` in the host SDK's `server/lifecycle.ts` supplies installation and disposal outcomes. Computerise marks a seat retained and publishes **available** only after `launch.onInstalled`; preparing a replacement does not replace the installed session's availability. Failed-open disposal releases only provisional allocations, after every concurrent opening using that seat has released it. Normal installed disposal never removes the retained seat or mode. Host-retained contributions hold their prior cleanup lifetime until dependents release it. These boundaries still require targeted tests, actual-plugin integration and visible UI verification before release. No settings or stored data migration is performed.

## Safety and data

- Screenshots and accessibility snapshots are returned to the agent and are therefore sent to that agent's model provider. Because new agents start in ask mode, they can take them without asking until you set them to Off. The Computer panel also shows the latest screenshot in the connected Paseo app. Each capture is written to a temporary file in the plugin's private folder and deleted as soon as it is read; after that, the latest screenshot is held only in plugin memory, and the panel downloads it only when a new one is taken.
- Every input action reads the front window's accessibility controls just before and just after it and returns what changed to the agent, so that text reaches the model provider without a separate request. An app blocked from view is never read.
- **Check Screen Recording** in the panel captures one point of the menu bar corner to a temporary file and deletes it; the image is not shown or sent anywhere.
- With **Show agents only the front app** on, screenshots and zooms contain only the front app's windows at their real positions; everything else, including the menu bar and Dock, is black. If macOS returns none of the app's windows, the capture fails rather than falling back to the full display.
- Computer use weakens an agent provider's filesystem or command sandbox because an agent can operate signed-in desktop applications with your macOS user permissions.
- Ask mode helps prevent mistakes and actions caused by instructions embedded in pages, email, or documents. It is not a security boundary against a hostile agent that can already run arbitrary local commands.
- Paseo itself, terminals, code-running apps, System Settings, and password managers are always blocked. An app inside a blocked app's bundle, such as the Passwords menu-bar helper or the tools inside Xcode, is blocked the same way as that app, including for apps added in the settings. A screenshot or accessibility snapshot is refused when a password manager is frontmost. With the default full-display setting, other visible windows can appear in a screenshot, but every window of a password manager or of an app hidden in the settings is painted black in screenshots and zooms, along with anything that overlaps it; if such a window moves or appears while the image is taken, the image is refused. A window that opens and closes within that moment is not covered. The settings screen can add bundle IDs; while the settings are invalid, tools that see or touch the screen refuse rather than act without those additions. Paseo cannot be unblocked, so an agent cannot press its own approval button through these tools.
- Approving from a phone is preferable when available because pressing Allow in the desktop app changes the foreground application. Computerise restores and rechecks the intended target before acting.
- Keys go to the app in front, so typing and key presses check that app before the first key and every 20 characters; if another app has come forward, they stop and report how many characters were typed.
- Audit logs contain the time, agent, tool, target application, and outcome. Typing records only the character count, never the text. Logs rotate at 5 MB and keep one previous file.

## Limits

Computerise controls only the main display and takes over the real pointer and keyboard. Electron apps such as Slack expose little more than their window frame to the text accessibility snapshot, so text-only models see little of them. It does not provide background window control. It supports macOS only. Some providers may not pass MCP image results to the model; agents can use the text accessibility snapshot instead. Existing saved endpoints retain their original address until explicitly adopted; the plugin never moves the tool server to another port automatically.
